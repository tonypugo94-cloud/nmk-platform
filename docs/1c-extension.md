# ТЗ для специалиста 1С

## Часть 1. Чтение (нужно сразу)

1. Резервная копия базы.
2. Публикация базы на веб-сервере (Apache/IIS) с флажком «Публиковать стандартный интерфейс OData».
3. Состав интерфейса OData: документ «Заказ клиента», справочники «Контрагенты», «Контактные лица», «Номенклатура», «Склады», регистр остатков товаров на складах, план видов характеристик «Дополнительные реквизиты и сведения», справочник «Значения свойств объектов».
4. Пользователь `obmen_nmk`: без интерактивного входа, роль удалённого доступа к OData, только чтение.
5. Дополнительный реквизит заказа клиента «Стадия производства», тип — значения свойств: «Принят», «В производстве», «Готов», «Установлен». При отсутствии отдельных полей — реквизиты «Кладбище», «Участок», «Телефон».
6. Проверка: `/odata/standard.odata/$metadata` открывается под `obmen_nmk`.

Имена реквизитов, если они отличаются, задаются у нас в настройке `ONEC_FIELDS` — 1С под нас менять не нужно.

## Часть 2. Запись стадий (только если включают модуль «Запись в 1С»)

Расширение конфигурации (основная конфигурация не меняется) с HTTP-сервисом `nmk`, шаблон `/stage`, метод POST:

```json
{ "ref": "<Ref_Key заказа клиента>", "stage": "Готов" }
```

Действие: найти заказ по ссылке, установить дополнительный реквизит «Стадия производства» в значение с таким наименованием, записать без проведения. Ответ `200 {"ok": true}`; заказ не найден — `404`; значение не найдено — `422`. Доступ — тот же пользователь `obmen_nmk` с правом на запись только этого реквизита.

Адрес сервиса передаётся нам в `ONEC_HS_URL`, например `https://1c.nmk.local/base/hs/nmk`.
