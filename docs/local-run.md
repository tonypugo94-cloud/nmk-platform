# Локальный запуск и проверка (Windows / macOS / Linux)

Всё работает на демо-данных: заказы приходят из встроенного эмулятора 1С, реальная 1С и токены ботов не нужны.

## 0. Что установить один раз

- **Git**, **Node.js 22**, **pnpm 9**: `npm i -g pnpm@9.15.0`.
- **Docker Desktop** (на Windows — с WSL 2). Запустите его и дождитесь статуса «Engine running».

## 1. Код и зависимости

```powershell
git clone https://github.com/tonypugo94-cloud/nmk-platform.git
cd nmk-platform
pnpm install
```

## 2. Supabase на своём компьютере

```powershell
npx supabase@2.122.1 start
```

Первый запуск скачивает образы, это 5–15 минут. Supabase сам применит все миграции из `supabase/migrations` и демо-справочники из `supabase/seed.sql`: направления, кладбища, машины, бригады.

В конце команда выведет адреса:

| Что | Адрес |
| --- | --- |
| API | http://127.0.0.1:54321 |
| Studio (админка базы) | http://127.0.0.1:54323 |
| База | postgres://postgres:postgres@127.0.0.1:54322/postgres |

Если команда остановилась на ошибке в миграции, пришлите текст ошибки целиком.

## 3. Ключ для интерфейса

```powershell
npx supabase@2.122.1 status -o env
```

Из вывода возьмите `API_URL` и `ANON_KEY`. Создайте файл `apps/web-office/.env.local`:

```
VITE_SUPABASE_URL=http://127.0.0.1:54321
VITE_SUPABASE_ANON_KEY=<ANON_KEY из вывода>
```

## 4. Первый администратор

1. Откройте Studio → **Authentication** → **Users** → **Add user** → **Create new user**.
2. Укажите почту и пароль, отметьте **Auto Confirm User**.
3. Studio → **SQL Editor**, выполните:

```sql
select core.bootstrap_admin('ваша@почта.ru', 'Антон Пуговкин');
```

## 5. Сервисы и эмулятор 1С (второе окно терминала)

```powershell
pnpm dev
```

Команда запускает эмулятор 1С с тремя заказами и все сервисы, каждый под своей ролью БД. Боты и погода пропускаются, пока не заданы их токены. Через несколько секунд в логе каждого сервиса появится `service started`, а заказы загрузятся в базу.

Проверка, что сервис жив: http://127.0.0.1:8101/health (accounting-sync). Порты остальных сервисов скрипт печатает при старте.

Можно запустить только часть сервисов: `pnpm dev accounting-sync planning messaging`.

## 6. Интерфейс (третье окно терминала)

```powershell
pnpm --filter @nmk/web-office dev
```

Откройте http://localhost:5173 и войдите под администратором.

## 7. Что проверить

1. **Модули.** Меню «Модули» → включите «Заказы», «Установки», «Клиенты», «Закупки» (это первая очередь). Остальные модули — вторая очередь, их тоже можно включить. Обновите страницу: в меню появятся разделы.
2. **Заказы.** Видны три заказа из эмулятора:
    - НМК-004812 «Готов» (Новое Кстово);
    - НМК-004790 «В производстве» (Арзамас);
    - НМК-004835 «Принят».

    Откройте карточку заказа: состав, сроки, история.
3. **Установки.** НМК-004812 стоит в списке готовых. Назначьте день, машину и бригаду, проследите за тоннажем, распечатайте накладную. Проверьте резервную пятницу и перенос заказа с указанием причины.
4. **Клиенты.** Покажите QR-код подключения к боту и шаблоны сообщений. Без токенов MAX/VK сообщения встают в очередь и видны в журнале.
5. **Закупки.** Задайте поставщику правило дозаказа по стеле: минимум и страховой запас. Пересчитайте потребность: остаток из 1С — 9 шт.
6. **Устойчивость.** Остановите сервисы (Ctrl+C в окне `pnpm dev`). Интерфейс продолжает работать: заказы видны, планирование доступно. Должен появиться баннер о том, что обмен с 1С не работает. Запустите `pnpm dev` снова — сервисы догонят пропущенные события.
7. **Телефон.** В браузере откройте инструменты разработчика (F12) и включите режим мобильного устройства. Чтобы открыть систему с настоящего телефона в той же Wi-Fi сети:
    - запустите интерфейс с флагом `--host`: `pnpm --filter @nmk/web-office dev -- --host`;
    - в `.env.local` замените `127.0.0.1` на IP компьютера;
    - откройте адрес, который выведет Vite.

## 8. Погода и автоплан

1. Включите модули «Погода» и «Автоплан».
2. Запустите сервисы с доступом к МетеоПлану (учётная запись НМК в кабинете МетеоПлана):

```powershell
$env:METEOPLAN_URL="https://qijgnekwakgwgqeibphw.supabase.co"; $env:METEOPLAN_KEY="<публичный ключ>"; $env:METEOPLAN_EMAIL="..."; $env:METEOPLAN_PASSWORD="..."; pnpm dev
```

3. Сервис погоды сам сопоставит направления с городами по названию. Прогноз появится в календаре «Установки» в ячейках дней.
4. На экране «Установки» нажмите «Собрать план сейчас». Готовый заказ встанет в машину на послезавтра, если погода позволяет. В плашке «Автоплан» видно, на какой день собран план и что не поставлено и почему.

Без доступа к МетеоПлану автоплан тоже работает, только не учитывает погоду.

## 9. Боты на реальных токенах (по желанию)

1. Создайте тестового бота в MAX и/или тестовое сообщество VK.
2. Сделайте публичный адрес до компьютера, например через туннель cloudflared или ngrok.
3. Запустите сервисы с токенами:

```powershell
$env:MAX_TOKEN="..."; $env:MAX_WEBHOOK_SECRET="..."; pnpm dev
```

Вебхуки и настройки описаны в `docs/deploy.md`, п. 8.

## 10. Автотесты

66 тестов запускаются в GitHub Actions при каждом пуше: вкладка **Actions** репозитория. Для запуска у себя нужен отдельный PostgreSQL 16 на порту 54329 (см. README, раздел «Разработка»). Не направляйте тесты на базу Supabase — они пересоздают схему.

## 11. Остановить и начать заново

- Сервисы и интерфейс — Ctrl+C.
- Supabase — `npx supabase@2.122.1 stop`.
- Вернуть базу к чистому состоянию с демо-справочниками — `npx supabase@2.122.1 db reset`. После этого заново создайте администратора (шаг 4).
